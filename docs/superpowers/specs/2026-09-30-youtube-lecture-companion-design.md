# YouTube 강의 학습 보조 Codex 플러그인 설계

## 목적과 범위

사용자는 Codex에 다른 채널의 공개 유튜브 강의 링크를 입력한다. 플러그인은 사용자의 컴퓨터에서 접근 가능한 자막을 확보하고 정제한 뒤, 한국어 자막 전문, 메인/세부 목차, 강의 전체 요약 노트, 용어집을 만든다. 이 결과를 JSON 한 건으로 운영자의 Railway 서버에 업로드하고, 링크를 아는 사람이 읽을 수 있는 웹 페이지 URL을 돌려준다. 운영자는 플러그인을 지인에게 GitHub 저장소 마켓플레이스로 공유한다. 설치자는 서비스 가입이나 개별 API 키 발급 없이 사용한다.

첫 버전은 링크 한 개를 한 번에 처리한다. 계정, 공동 편집, 재처리 이력 화면, 영상 음성의 별도 전사, 공식 공개 플러그인 디렉터리 제출은 범위에 넣지 않는다. 자막을 자동으로 확보하지 못하면 원인을 표시하고 저장 전에 중단한다.

## 실행 구조

1. Codex 플러그인의 식별자는 `youtube-lecture`이며 `plugins/youtube-lecture/`에 배치한다. `.codex-plugin/plugin.json`과 강의 처리 스킬, 로컬 Python 보조 스크립트로 구성한다. 저장소 루트의 `.agents/plugins/marketplace.json`이 플러그인을 가리킨다. 사용자가 링크를 주면 스킬이 작업 순서를 안내한다. 설치 후 별도 계정·키 입력은 요구하지 않으며, 필요한 로컬 의존성 설치는 플러그인 흐름에서 안내하거나 자동화한다.
2. 자막 수집 스크립트는 유튜브 URL을 영상 ID로 제한하여 해석하고, 공개된 수동 또는 자동 생성 자막을 로컬에서 읽는다. 한국어 자막을 우선하고, 없으면 접근 가능한 다른 언어의 자막을 사용한다. 수집 응답의 텍스트와 시작/지속 시간을 보존한다.
3. Codex는 자막의 반복, 분절, 불필요한 표기를 정리한다. 원문이 한국어가 아니면 자막 전문을 한국어로 번역하고 이를 웹에서 번역본으로 표시한다. 긴 자막은 시간 순서의 작은 구간으로 나누어 처리한 후 전체 흐름을 종합한다. 모델은 자막에 없는 내용을 사실로 보태지 않는다.
4. Codex는 메인/세부 목차, 강의 전체 요약과 구간별 노트, 용어집을 생성한다. 목차와 노트와 용어는 근거가 되는 자막의 영상 시점을 가진다. 업로드 전 로컬 검증기가 형식과 시점을 검사한다.
5. 검증이 끝난 JSON만 Railway 서버의 업로드 API에 HTTPS로 보낸다. 서버는 PostgreSQL에 JSON을 저장하고 추측하기 어려운 공유 ID를 발급한다. 웹 페이지는 이 ID로 결과를 읽어 표시한다. 서버의 공개 기본 URL은 플러그인에 설정하되 운영 비밀은 포함하지 않는다.

자막 수집은 플러그인에서 수행한다. Railway의 클라우드 IP에서 유튜브 자막을 직접 수집하지 않는다. Codex의 모델이 내용 분석을 담당하므로 첫 버전에 별도 AI 서비스 키를 요구하지 않는다.

## JSON 계약

최상위 필드는 `schema_version`, `video`, `transcript`, `outline`, `summary`, `glossary`이다. `schema_version`의 첫 값은 `1`이다.

- `video`: `youtube_id`, `url`, `title`, `source_language`, `transcript_language`(`ko`), `is_translated`, `processed_at`을 포함한다. 제목을 확보하지 못하면 영상 ID 기반 표시명을 쓸 수 있다.
- `transcript`: 시간 순서 배열이다. 각 항목은 `start_ms`, `duration_ms`, `source_text`, `ko_text`를 포함한다. 정제와 번역 후에도 원문과 원래 시점은 남긴다. 웹에는 `ko_text` 전문을 표시한다.
- `outline`: 메인 목차 배열이다. 각 항목은 `title`, `start_ms`, `children`을 포함한다. 세부 목차 항목은 `title`, `start_ms`를 가진다. 시간은 오름차순이며 영상의 자막 범위를 벗어나지 않는다.
- `summary`: `overview`와 `sections`를 포함한다. 각 구간 노트는 `heading`, `body`, `source_start_ms`를 가진다. 강의 전체를 아우르는 개요와 구간별 핵심 설명을 함께 제공한다.
- `glossary`: `term`, `definition`, `source_start_ms` 항목의 배열이다. 강의에서 실제 언급된 핵심 용어를 설명한다.

검증기는 문자열 공백값, 필수 배열의 빈 값, 중복되거나 역전된 자막 시점, 범위 밖 근거 시점, 과도한 JSON 크기를 거부한다. 실패하면 오류를 Codex에 보여주고 서버에 업로드하지 않는다. 자막 원문에 결함이 있더라도 모델이 임의 사실로 메우지 않으며, 판별할 수 없는 항목은 생성하지 않는다.

## 서버와 공개 화면

- `POST /api/lectures`: 가입이나 키 없이 업로드를 허용하되 JSON 계약을 다시 검증한다. 요청 본문은 4 MiB로 제한한다. 동일 IP의 업로드는 24시간에 5건, 서비스 전체는 24시간에 100건으로 제한한다. 한도 초과 시 재시도 안내를 포함한 `429`를 반환한다. 유효하면 한 건으로 저장하고 공유 URL을 반환한다. 한도 값은 Railway 환경 변수로 조정할 수 있다. 이 제한은 오용을 완전히 막지 못하므로 운영자는 사용량을 확인할 수 있어야 한다.
- `GET /api/lectures/{share_id}`: 공유 ID에 해당하는 공개 결과를 반환한다. 전체 목록을 조회하는 공개 API는 두지 않는다.
- `GET /lectures/{share_id}`: 제목, 유튜브 영상, 2단 목차, 전체 요약 노트, 용어집, 검색 가능한 한국어 자막 전문을 보여준다. 목차·노트·용어·자막의 시점을 선택하면 해당 영상 시점으로 이동한다. 원문이 외국어면 자막 전문에 번역 표시를 한다. 모바일에서도 읽을 수 있어야 한다.
- 공유 ID는 무작위로 생성하며 충분히 길게 만든다. 공개 페이지는 링크를 가진 누구나 읽을 수 있다. 검색 엔진 색인 방지 지시를 넣는다. 자막과 생성 텍스트는 HTML로 렌더링할 때 이스케이프한다.
- 재실행은 별도 공유 결과를 만든다. 첫 버전에는 공개 수정·삭제 기능이 없다.

## 오류 처리

유효하지 않은 유튜브 URL, 비공개·연령 제한·지역 제한 영상, 제공되지 않는 자막, 수집 차단, 빈 자막, 생성 결과 검증 실패를 구분해 사용자에게 짧고 구체적으로 알린다. 자동 자막 실패 시 다른 입력이나 음성 전사로 자동 전환하지 않고 중단한다. 업로드 실패 시 검증된 JSON을 로컬에 남겨 재전송할 수 있게 하고, 성공한 공유 URL을 추측해 표시하지 않는다. 서버는 형식 오류, 요청 한도 초과, 저장 오류를 구분된 HTTP 상태로 반환한다.

## 검증과 완료 기준

- URL 형식과 영상 ID, 자막 언어 선택, 자막 시점 보존, 자막 수집 실패를 단위 테스트한다.
- 정제 및 생성 단계는 짧은 한국어와 외국어 자막, 긴 자막의 분할을 고정 샘플로 검증한다. 번역 여부 표기와 모든 항목의 근거 시점을 확인한다.
- 서버 계약 테스트는 잘못된 JSON, 4 MiB 본문 초과, IP별·전체 업로드 한도, 정상 저장·재조회, 찾을 수 없는 공유 ID를 확인한다.
- 브라우저 확인은 목차·요약·용어·자막 전문 표시, 자막 검색, 시점 이동, 모바일 배치를 확인한다.
- 실제 공개 영상 한 건으로 로컬 플러그인에서 JSON 생성까지, Railway 배포 환경에서는 업로드부터 공유 페이지 표시까지 확인한다. 새 환경에서는 저장소 마켓플레이스 추가와 플러그인 설치 후 강의 링크만으로 처리되는지도 확인한다. 실제 외부 배포에는 사용자의 Railway 프로젝트 접근 정보와 GitHub 인증이 필요하다.

## 배포와 공유

Git 저장소에는 플러그인, 저장소 마켓플레이스 목록, 서버 코드, 설치·운영 안내를 함께 둔다. GitHub에 공개 저장소로 게시하면 지인은 `codex plugin marketplace add <owner>/<repo>`로 소스를 추가하고 플러그인을 설치할 수 있다. 저장소 게시 자체가 공식 공개 플러그인 디렉터리 등재를 뜻하지 않는다. Railway는 같은 저장소의 서버 디렉터리를 배포 대상으로 사용하고 PostgreSQL을 연결한다. 서버 URL을 확정하면 플러그인의 기본 설정에 반영한다. 개인 토큰, Railway 비밀 값, 실제 자막 결과는 저장소에 커밋하지 않는다.

## 결정 근거와 한계

YouTube Data API의 자막 목록은 자막 본문을 반환하지 않으며 자막 다운로드는 OAuth 권한을 요구한다. 다른 채널의 공개 영상은 로컬 공개 자막 수집 경로를 사용한다. 이 경로는 유튜브의 제공 상태와 접근 제한에 따라 실패할 수 있어 성공을 보장하지 않는다. 실패 시 작업을 명확히 중단하는 것이 첫 버전의 계약이다. 공개 자막 수집 도구는 클라우드 IP 차단 가능성을 알리고 있으므로 수집을 Railway로 옮기지 않는다.

참고: [YouTube Captions API](https://developers.google.com/youtube/v3/docs/captions/list), [youtube-transcript-api](https://github.com/jdepoix/youtube-transcript-api), [Railway PostgreSQL](https://docs.railway.com/databases/postgresql).
