# youtube-lecture 공개 목록과 영상 중심 상세 화면 설계

## 배경과 결정

기존 공유 페이지는 요약 노트가 화면의 넓은 영역을 차지하고 영상이 오른쪽의 좁은 영역에 놓인다. 사용자는 영상을 중심으로 학습하면서 목차, 요약, 용어집을 필요할 때 전환해 보고, 자막은 영상 바로 아래에서 스크롤하며 읽기를 원한다. 또한 서버에 저장된 강의를 첫 화면의 목록에서 골라 상세 페이지로 들어가기를 원한다.

이 문서는 [2026-09-30 최초 설계](2026-09-30-youtube-lecture-companion-design.md)의 웹 화면과 공개 범위를 갱신한다. 플러그인의 자막 수집, 내용 생성, JSON 계약, 업로드 API, 기존 공유 URL은 유지한다. 사용자가 확인한 새 공개 범위는 **서버에 저장된 모든 강의를 로그인 없이 목록으로 열람**하는 것이다. 목록과 상세에는 `noindex`를 유지한다. 이는 검색 엔진에 검색 결과 노출을 피하도록 요청하는 표시이며 접근 제어가 아니다. 도메인을 아는 방문자는 목록과 상세의 한국어 자막 전문을 볼 수 있다.

## 접근 방식

FastAPI와 Jinja 템플릿으로 목록 및 상세 HTML을 서버에서 만든다. 기존 CSS 변수와 타이포그래피를 이어 쓰고, 상세의 탭 전환과 자막 검색·시점 이동만 작은 JavaScript로 처리한다. 별도 프런트엔드 앱이나 공개 목록 API는 추가하지 않는다. 저장소는 목록에 필요한 작은 메타데이터만 조회해, 자막 전문을 모든 카드와 함께 읽어 오지 않는다.

## 첫 화면: 강의 목록

- `GET /`가 강의 목록이다. 저장 시각의 최신순으로 24건씩 카드에 표시한다. 다음 페이지가 있으면 페이지 이동 링크를 제공한다. 페이지 번호가 범위를 벗어나면 빈 상태를 보여준다.
- 카드에는 YouTube 썸네일, 강의 제목, 처리 날짜, 원문 언어, 메인 목차 개수를 표시한다. 카드 전체를 선택하면 기존 `GET /lectures/{share_id}` 주소로 이동한다. 새로고침과 직접 링크 모두 동작한다.
- 저장된 강의가 없으면 빈 상태와 Codex 플러그인으로 강의를 추가하는 짧은 안내를 보여준다. 영상 썸네일을 받지 못해도 제목과 링크를 읽을 수 있어야 한다.
- 제목과 메타데이터는 HTML 이스케이프를 적용한다. 목록에는 `X-Robots-Tag: noindex, nofollow` 및 HTML `noindex` 표시를 넣는다. 상세의 색인 방지와 공유 주소도 유지한다.
- 기존 배포 검증용 가짜 영상 데이터는 공개 목록 전환 전에 제거한다. 실제 강의 결과만 첫 화면에 보인다.

## 상세 화면: 영상, 자막, 탭

- 상단에는 목록으로 돌아가는 링크, 강의 제목, 메타데이터, 공유 링크 복사 버튼을 둔다.
- 데스크톱은 왼쪽을 넓게 사용하는 두 열이다. **왼쪽: 16:9 영상 → 영상 바로 아래 자막 검색과 스크롤 가능한 한국어 자막 전문. 오른쪽: 목차 / 강의 요약 / 용어집 탭.** 오른쪽 패널은 영상 상단에 맞추고, 내용이 길면 패널 안에서 스크롤한다. 선택한 탭은 시각적 강조와 `aria-selected`로 드러난다.
- 목차 탭은 메인·세부 목차와 시점을 유지한다. 요약 탭은 강의 전체 개요와 구간별 노트를 함께 보여준다. 용어집 탭은 용어, 해설, 등장 시점을 보여준다. 자막 행에도 시점 링크를 둔다. 시점을 누르면 현재 임베드 영상이 그 위치로 이동한다.
- 자막 영역에는 검색 입력, 일치 구간 수, 결과 없음 상태를 둔다. 자막 내용은 기존처럼 `ko_text` 전문을 표시하고 번역 여부를 밝힌다. 자막 목록만 높이를 제한해 스크롤하며, 페이지 전체를 끝없이 늘리지 않는다.
- 좁은 화면에서는 **영상 → 자막 → 탭 패널** 순서로 한 열에 쌓는다. 탭 버튼은 화면 폭 안에서 읽히고 조작돼야 한다. 영상 비율은 유지한다.
- 탭은 버튼과 패널을 연결하는 접근성 속성을 갖고, 클릭과 좌우 방향키, Home/End 키로 이동할 수 있어야 한다. JavaScript가 실행되지 않아도 세 내용에 접근 가능한 기본 표시를 제공한다. 기존 자막 검색, 공유 링크 복사, 영상 시점 이동은 계속 작동한다.

## 서버와 데이터 흐름

- PostgreSQL `lectures`의 기존 `share_id`, `payload`, `created_at`에서 카드 메타데이터만 읽는 `list` 메서드를 추가한다. 조회는 안정적인 최신순(`created_at DESC`, `share_id DESC`)이고 한 번에 25건을 읽어 다음 페이지 존재 여부를 판단한다. 필요한 정렬 인덱스를 기존 테이블에 안전하게 추가한다.
- `GET /`는 목록 메서드의 결과를 템플릿에 전달한다. 저장소 장애는 기존 서버 오류 처리 방식으로 503을 반환한다. 업로드와 상세 조회의 계약, 저장된 JSON, 기존 강의 상세 URL은 바꾸지 않는다.
- `POST /api/lectures` 성공 후 받은 공유 URL은 그대로 상세로 연결된다. 첫 화면에는 새 강의가 최신 항목으로 나타난다. 재처리한 영상은 각각의 결과로 표시하며 과거 공유 URL도 계속 유효하다.

## 검증 기준

- 목록이 최신순으로 보이고 24건 단위 페이지 이동과 빈 상태가 동작한다. 목록 카드가 올바른 상세 URL로 연결된다. 기존 공유 URL은 그대로 열린다.
- 데스크톱에서 영상이 왼쪽의 주 영역, 자막이 그 바로 아래, 세 탭이 오른쪽에 나타난다. 모바일에서 영상→자막→탭 순서로 쌓이며 가로 넘침이 없다.
- 탭 클릭과 키보드 전환, 자막 검색, 시점 이동, 링크 복사 기능을 브라우저에서 확인한다. CSS와 JS는 HTTPS 공유 페이지에서 정상 로드된다.
- 목록과 상세가 모두 `noindex`를 표시한다. 공개 목록의 제목은 HTML로 실행되지 않는다.
- 전체 테스트를 통과하고 Railway 배포 후 실제 강의 목록과 상세를 직접 확인한다.
